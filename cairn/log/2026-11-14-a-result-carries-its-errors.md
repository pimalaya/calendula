# A result carries its errors

Following Himalaya's change of the same name and neverest's a-refusal-carries-its-code (both 2026-11-14): a listing prints an `errors` list beside its items, one pimalaya-cli item error `{id, code, error, sources}` per calendar or item it could not read, and exits 3 when it is not empty; a server's refusal and a missing item or calendar carry a code. Four phases, one commit each.

- **Phase 1, the libraries** (86e7fa4, `build: update pimalaya-stream to 0.4 and the io-* crates`): pimalaya-stream 0.4, io-http 0.8, io-msgraph 0.9, dev io-oauth 0.7, pimalaya-config 0.4.1 (a prompting credential command reads the terminal again); `[patch.crates-io]` pins io-gcal dbb4481 and pimalaya-cli 0be1b1f (its `ItemError`), and links io-pim-discovery by `path = "../io-pim-discovery"` (its stream-0-4 commit 1c3d195, not pushed; owner ruling). `TlsConfig::into_tls` maps `tls.cert` to `TlsServer`. `cargo tree -d` lists no family crate twice.
- **Phase 2, the codes** (1dea5cb, `feat: code a server's refusal and a missing item or calendar`): `permission-denied`, `quota-exceeded`, `rate-limited`, `item-not-found`, `calendar-not-found` and `item-unreadable` in src/error.rs, declared in every build; one `refusal_code` reader per protocol (CalDAV, Google Calendar with a copy of neverest's `google_code`, Graph) walked by `error::code`, and `error::with_code` (ortie's pattern) applied where a command and the MCP server end, so the failure object reads a refusal's code. `precondition-failed` covers every backend (a 412, Graph's `--if-match` mismatch), `item-duplicate` CalDAV's `no-uid-conflict`. `event delete` falls back to a full listing on `item-not-found` alone; `account check` rows read their code through `error::code`.
- **Phase 3, the listings** (f3dca04, `feat!: list the calendars and items a listing could not read`): every backend's `list_items` returns `CalendarItemList {items, errors}`; `calendar list`, `event list`, `event find`, `event agenda` and `item list` print `errors` and exit 3 through `PartialOutcome`; the agenda's JSON root is `{starts, errors}`; vdir reads through io-vdir 0.3's `list_readable_items`; a Graph re-read refused is an entry, a 404 left out; pimdir names a body it cannot serve and a hydrated body that does not parse. The text lists print their paging in their header and the `Error:` lines last, a local copy of pimalaya-cli 79c0d9e's `ItemErrors` (unpushed). `calendula-item-error` is registered; the MCP listing tools answer `isError: true` with `structuredContent.errors`; the REPL keeps its client after an exit-3 line.
- **Phase 4, CalDAV rows** (`feat: list the CalDAV rows a listing could not read`): `[patch.crates-io]` links io-webdav by `path = "../io-webdav"` (its a-listing-returns-what-it-could-not-read, 4ecb2ab, not pushed; owner ruling), replacing the 185ab63 pin. `CaldavBackend::list_items` reads `CaldavItemListOk`: each `WebdavUnreadableEntry` is an entry naming its item, coded from its row status or the status refusing its properties through `caldav::client::row_code` (the Phase 2 reader's status rule, a 403 `permission-denied`), else `item-unreadable`, each refused property in `sources`; `truncated` (a 507 row) is an entry with a `null` id and no code. Entries print on the first page only. No calendula command calls a CalDAV multiget, so nothing else moved.

Departures from the plan:

- `calendar-unreadable` was left out: io-vdir 0.3's `list_collections` fails whole on an unreadable metadata file, so no backend meets it, and `calendar list` always prints `"errors": []`.
- The kind filter (`may_hold_kind`, renamed from `holds_kind`) and the range filters (`starts_within`, pimdir's `in_range`) keep an item that does not parse, else vdir and pimdir would drop it before the command could name it.
- The paging rule was refined: an item listed but not readable (an iCalendar that does not parse, a pimdir body the store cannot serve) holds its place on a page, so its entry prints on that page on every backend; only what holds no place (a vdir file not read, a refused Graph re-read, a CalDAV row without data or a truncation) prints on the first page alone.
- `event delete` reads a pimdir `body-pending` answer as naming the item, as it read any successful lookup.

Evidence. Each phase's tests ran through the real error path and failed before it. Phase 2: scripted CalDAV, Google Calendar and Graph streams answering 403, 404, 410, 412, 429, 507 and `no-uid-conflict` (`a_refused_write_carries_its_code`, `a_duplicate_uid_and_a_stale_version_carry_their_code`, `an_item_the_server_does_not_hold_is_not_found`, `a_refusal_carries_its_code`, `a_moved_change_key_refuses_the_delete_as_a_precondition`), `a_refused_lookup_fails_coded_and_lists_nothing` (a scripted Graph 403 to the `event delete` lookup), tests/read.rs `an_unknown_id_is_coded_not_found`. Phase 3: tests/event_list.rs over a temp vdir holding an unparseable `.ics` and a `chmod 000` file (two entries, exit 3, the agenda's `starts`), `a_refused_reread_is_an_entry_and_a_gone_one_is_left_out` (Graph), `a_body_the_store_cannot_serve_is_an_entry_on_its_page` (pimdir), tests/mcp.rs `a_listing_with_errors_answers_its_payload_as_a_tool_error`, tests/repl.rs `a_partial_outcome_keeps_the_session_client`, the text tests for the moved paging and the `Error:` lines. Phase 4: `a_caldav_listing_names_the_rows_it_could_not_read`, a scripted multistatus holding an item, a 403 row, a row whose `calendar-data` propstat is refused 403, a row without data and a 507 row (four entries: `permission-denied` twice, `item-unreadable`, the `null`-id truncation), and `a_caldav_listing_names_its_rows_on_the_first_window_only`; both fail on the Phase 3 code, which returned no entry for CalDAV. Every phase: `cargo fmt`, then `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked` over the eleven feature sets of the CI `features` job, and `sh cairn/verify.sh`; at the landing `--all-features` ran 302 unit tests, tests/account_check.rs 3, capability 9, event_list 8, first_run 6, mcp 13, read 3, repl 7, usage 2. The live suites (Google, Microsoft, Fastmail) were not run.

Capabilities moved: commands (cairn/spec/commands.md: "A listing names the items it could not read" and "A command's errors print at its end" added; "A JSON error carries a stable code", "The JSON contract is described and versioned", "A refused command line exits 2", "Text output is plain text", "An agenda shows every event at an instant" and "An event is deleted by its id or its UID" modified), backends (cairn/spec/backends.md: "A server's refusal carries its code" and "Each backend names the items it could not read" added; "pimdir is an availability-aware cache" and "CalDAV backend" modified), mcp (cairn/spec/mcp.md: "A tool's output is the command's payload").
