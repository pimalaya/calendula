# The releases of 2026-11-24

Calendula moves to the libraries released on 2026-11-24, every one from crates.io: io-pimdir 0.20.0 (the storage-draft-17, sync-draft-15 and search-draft-17 revision it pinned by git at 65a5026, `[patch.crates-io]` removed), io-jmap 0.11.1, io-msgraph 0.11.0, io-webdav 0.14.0 and pimalaya-cli 0.8.1. `cargo update -p` on those crates moved them alone in Cargo.lock; no git or path source is left.

- **JMAP (C1b of the-live-night-findings)**: io-jmap 0.11.1's `JmapCalendarEvent::from_ical` keeps the JSCalendar Group's `version`, so a written event carries `version: "2.0"`, which Fastmail requires of a create. projection.md names it. Live on fastmail-jmap, in calendar `live-2026-11-24-calendula-3`, created and deleted: create (`DTSTART`/`DTEND`), update and delete passed, where the create failed `invalidProperties` (`version`) on io-jmap 0.11.0.
- **Graph**: io-msgraph 0.11.0 creates an event without `DESCRIPTION` with no body, which Exchange no longer rewrites seconds after the create. The new `MsgraphEvent` and `MsgraphCalendar` fields reach no struct literal here (every one spreads `..Default::default()`).
- **CLI**: pimalaya-cli 0.8.1 makes `--log-file` refuse a symbolic link to an existing file, as its help says.
- **CalDAV**: io-webdav 0.14.0 returns the member rows a `sync-collection` REPORT or its `PROPFIND` fallback answered with an error status as `WebdavSyncDelta::unreadable`, where it dropped them. `caldav report sync` does not print them yet, as before.
- **Tests**: the JMAP fixtures `get()` (src/jmap/backend.rs) and `series()` (src/jmap/project.rs) served an event without `version`, which Fastmail serves; the write now carrying it, `a_write_is_guarded_by_the_hash_of_the_event_it_reads` and `a_series_round_trips_through_its_document` found `version` in the patch. The fixtures now carry `version: "2.0"`.
