# Google Calendar protocol-specific family

gcal landed with a backend and no family, so the half of the Calendar API that iCalendar cannot express was unreachable. It has one now, in the shape `caldav` already had: its own client built from the account's `[gcal]` block, and one subcommand per resource the shared surface cannot carry.

## What landed

- **`calendars`**: the richer listing, as `caldav list` is to `calendar list`. A Google calendar list entry carries the access role the account has, whether it is the primary calendar, the time zone the series expand in and the default reminders a new event inherits, none of which fit the shared `Calendar`.
- **`acl`** (`list`, `create`, `update`, `delete`): the sharing rules. A rule id is `<scope type>:<scope value>`, minted by the API, so the write verbs take `--scope`, `--value` and `--role` and derive it; only `delete` takes the id, the one a listing showed.
- **`free-busy`**: availability over a window, for one or more calendars. This is the clearest case for the family existing at all: availability is a question, not a resource, so no component family could carry it.
- **`instances`**: the occurrences a recurring event expands to. The shared listing deliberately returns the series (that is what round-trips through the projection), so this is the only way to see the moved and cancelled occurrences a rule alone does not describe.
- **`move`**: relocating an event between calendars. The shared API would have to emulate it as a create plus a delete, minting a new id and dropping whatever the projection does not model.
- **`quick-add`**: an event from a sentence, parsed server-side.
- **`colors`** and **`settings`**: the two palettes the API's colour ids refer to, and the account's own time zone and week start.

`--from` / `--to` are inclusive days on `free-busy` and `instances`, as on `event list`, so one date spelling serves the whole CLI; they are mapped onto the RFC 3339 bounds the API takes by the same helper the backend uses, which moved into a shared `render` module rather than being written twice.

## Declined, on purpose

- **`channels` / `watch`**: a push channel delivers to an HTTPS endpoint the caller must host. A CLI has none, and standing one up is the push platform's job.
- **`calendars.transferOwnership`**: an irreversible administrative act on a Workspace domain.
- **`calendars.clear`**: empties the primary calendar with no undo, and `calendar delete` covers the secondary case.

These are recorded in the spec so a later reader does not read them as gaps.

## Capabilities moved

- **commands**: `gcal` joined the protocol-specific families, with its own requirement naming the eight subcommands and the scope-derived rule id, plus a requirement recording what the family declines and why.
