# The sample is tested and shipped

Change 5 of the-family-standards. config.sample.toml takes Himalaya's shape (himalaya 2026-11-11-the-sample-is-tested-and-shipped), from 196 lines of prose paragraphs to 72 lines of code.

- The file opens on `[accounts.example]`, no header comment, and lists the options every account shares with dotted keys: `default = true`, `calendar.default` (commented, no default existing: `event` and `item` need it or `-k`), `event.list.page-size = 25` and `item.list.page-size = 25` active with `0` (every item on one page) commented, and `item.composer` as a shell line (`"$EDITOR"`) and an argv list (`["tcal", "edit"]`), every line ending in one comment aligned per block at column 40 or the next tab stop past the block's longest line. The shared options moved from the top level into the account; the top level still takes them as the fallback of every account not setting them.
- Seven sections follow, each a paragraph headed `# <Name>` then `#`, holding a working account once uncommented, its own alternatives commented twice: CalDAV (`server` active, a bare authority, `discover` in its place and `home` over it commented; HTTP Basic with the `exit 127` password command and its `raw` form; `alpn`; the TLS provider, rustls crypto and certificate), Google Calendar (`gcal`, its token, `alpn` and TLS), Google CalDAV (`caldav.server` at the principal https://apidata.googleusercontent.com/caldav/v2/, whose discovery io-webdav's live Google suite walks, with a bearer token), Microsoft Graph (`msgraph`, `user-id`, `alpn` and TLS), Fastmail (`caldav.server` at https://caldav.fastmail.com/dav/, as io-webdav's live Fastmail suite connects, HTTP Basic with an app password, Fastmail's CalDAV taking no bearer token), vdir, pimdir. OAuth 2.0 tokens come from `["ortie", "token", "show", "-a", "example"]`, Ortie's sample holding the Google and Microsoft Graph sections. Every key was checked against src/config.rs.
- Fixed on the way: the pimdir root is neverest's shared store, ~/.local/state/neverest, not ~/.local/state/neverest/example; the file as copied no longer holds an active CalDAV account pointed at `caldav.example.org` with `pass show example`, nor an active vdir home.
- Not as code lines: the CalDAV authentication is an enum keyed by name, and `pimalaya_config::sample::variants` swaps a line only for the active line of the same key, so a `##caldav.auth.bearer.token` beside the active `caldav.auth.basic` lines would fail as a two-key enum. Basic (CalDAV, Fastmail) and Bearer (Google CalDAV) stand as code; `bearer.token` and `auth = "none"` are named in the comment of the CalDAV username line and in one README sentence. Arrays stay on one line (comodoro's trap: the helper reads no inline-table element inside a multi-line array). The old sample's prose lives in the spec already: the `auto` backend order, the gcal and Graph ids, the Graph series masters, the pimdir "body not fetched" (backends), the paths and `-c` (config).
- src/config.rs: `the_sample_configuration_parses_with_each_variant` requires the single `[accounts.example]` header, then parses each variant `variants(&sample, &headings)` returns through `Config::load`, the loader `-c` uses, resolves `example` as the default account and requires a backend block: 64 variants under `--all-features` (CalDAV 16, Google Calendar 11, Google CalDAV 6, Microsoft Graph 12, Fastmail 6, vdir 6, pimdir 7). `SECTIONS` pairs each heading with `cfg!` of its backend's feature, and a variant whose heading is not compiled is skipped, the loader ignoring a block whose backend the build leaves out: with `--no-default-features --features rustls-ring,vdir` the vdir section's 6 variants run, and without the skip that build fails on `# CalDAV` with no backend declared. The tests module imports `crate::config::*` in place of `super::*`. Cargo.toml: pimalaya-config 0.4 with `sample` as a dev-dependency, the released 0.4.0 carrying it.
- Seen failing on a scratch copy of the text: `##caldav.tls.rustls.crypt = "aws"` (the variant `# CalDAV, caldav.tls.rustls.crypt = "aws"` named, ``unknown field `crypt`, expected `crypto` ``), a `#gcal.user-id = "me"` line in the Google Calendar section (the base `# Google Calendar` named, ``unknown field `user-id`, expected one of `tls`, `alpn`, `auth` ``), and the old sample (``Section `# CalDAV` not found``). Not seen: a misspelled first-level account key, `#evnt.list.page-size = 0` passing, since the account block denies no unknown key so a build without a backend still loads a file naming it.
- package.nix installs config.sample.toml as share/doc/calendula/config.sample.toml; .github/workflows/releases.yml already calls pimalaya/nix's releases.yml, whose `build-with-share` job puts the build's share/ in every archive. install.sh copies it to $PREFIX/share/doc/calendula/ when the archive holds it (checked on a scratch prefix, with and without the file).
- README Configuration: the sample, its sections, Ortie, the shipped path and the welcome first, then the CalDAV authentication shapes, the top-level fallback, the paths and `-c`. The Google CalDAV snippet names the principal through `caldav.server` (`events` the primary calendar), where it pinned `caldav.home` and called the discovery off-spec; the Fastmail snippet takes `caldav.server` and a password command; the Graph and gcal tokens read `-a example`; the pimdir root is the shared store. CHANGELOG: the shipped sample added, the sample changed.
