# The wizard leaves

The owner decided on 2026-11-08 that the Pimalaya CLIs drop their wizards; Ortie and Himalaya already did. Change 3 of the-family-standards, on pimalaya-cli 0.3.2 and pimalaya-config 0.3 still.

- src/wizard/ (8 files, 2,245 lines, 36 tests) is gone, with the `configure` command and its `wizard` alias, the `wizard` cargo feature and its place in `default`, the pimalaya-cli `wizard`, `caldav` and `spinner` features it enabled, and shellexpand, the wizard being its only user. pimalaya-cli `prompt` stays for the composer's `Re-edit the item?`.
- Bare `calendula` prints the help, a configuration or not. `load_config` no longer offers anything: no configuration fails with `No configuration found at <path>, write one by hand from the sample: https://github.com/pimalaya/calendula/blob/master/config.sample.toml`, the one `NO_CONFIG_HINT` left in src/config.rs, with no cfg split. `account check` now loads through `load_config` too, so its message names the path where it named none. `load_config`, `resolve_account`, `CalendarClient::resolve`, `PimdirBackend::build` and the `build_*_client` builders no longer take the printer, which only the offer needed.
- src/config.rs: `AccountConfig::render`, `RENDER_ORDER`, `ENDPOINT_KEYS`, `CONFIG_SAMPLE_URL`, `is_default`, `is_default_msgraph_user_id`, the `skip_serializing` attributes of the `todo` and `journal` refusals and every `Serialize` derive are gone, nothing else serializing a configuration type: no `*Output` carries one, `Backend` derives none, and `crossterm`'s `serde` feature stays for the colours' `Deserialize`.
- src/account/check.rs: `all_ok`, called by the wizard alone, is gone and `check_account` is private. src/caldav/client.rs: `resolver`, which the wizard's lookup shared, folds into `resolve_server`, its one caller.
- io-pim-discovery stays for `caldav.discover`, which resolves a bare domain through RFC 6764 on every run: optional, pulled by `caldav` with `rfc6764` and `stream` only (`rfc6764::client` and `shared::dns::system_resolver` sit behind `client`, `with_tls` and `resolve` behind `stream`), its three TLS forwards weak. `autoconfig` and `pacc` leave, and with them 17 crates from the lock: block-buffer, block2, cfg_aliases, crypto-common, ctrlc, digest, dispatch2, hybrid-array, nix, objc2, objc2-encode, psl, psl-types, serde-xml-rs, sha2, typenum and xml. `cargo tree --no-default-features --features rustls-ring,vdir` builds no io-pim-discovery any more (289 lines of tree from 334), so a local-only build links no discovery code.
- src/json_schema.rs drops `calendula-configure`.
- README (the wizard feature bullet and TIP, the Configuration section, the Google and Microsoft sign-in sentences; the Discovery bullet now names `caldav.discover`), CONTRIBUTING (the `caldav` row names io-pim-discovery), the config.sample.toml header and its three wizard sentences, the src/main.rs header (its "Configuration" section), MIGRATION.md (No wizard, under 0.2.x -> unreleased), and the CHANGELOG: the nine Unreleased wizard entries give way to one Removed entry marked **Breaking.**, the io-pim-discovery 0.11 one trimmed to what reaches `caldav.discover`.
- first-run-wizard-frame is abandoned. wizard-discovery-first, wizard-runs-when-unconfigured and wizard-save-path move to changes/archive/, beside the-wizard-picks-and-asks-once. secret-resolver-per-account stays, its resolver serving `account check` and the backends. The jmap-backend proposal drops the follow-up wizard it listed out of scope.

Tests: tests/first_run.rs runs the built binary with stdin a pipe and a missing `-c` path. `a_bare_invocation_without_configuration_prints_the_help` failed on the old code, whose help listed `configure`; `a_command_without_configuration_names_the_path_and_the_sample` (`account list`, `account check`, `calendar list`) failed on the old message, `run calendula configure to generate one, or write it by hand`, `account check` naming no path at all. The 36 wizard tests and `a_rendered_account_spells_the_default_flag_only_when_it_is_set` left with their code: 247 unit tests and the 2 integration tests pass, from 284 unit tests.

Verified: `cargo fmt`; `cargo test --all-features`; `cargo clippy --all-targets -D warnings` with the default features, `--all-features`, and `--no-default-features --features rustls-ring` with each of vdir, caldav, gcal, msgraph and pimdir. `rustls-ring` alone still fails on the same 29 errors as before this change, in code it did not touch, for every-feature-set-builds-clean. `json-schema -d` of the new binary matches the old one's byte for byte but for the missing `calendula-configure.json`: 48 schemas with all features. `calendula --help` lists no `configure`.

Spec: wizard removed whole (spec/wizard.md); config (A missing configuration is an error, The configuration is never written added; A defaulted scalar is not written back removed), commands (Protocol-specific families modified) and packaging (One cargo feature per backend modified: `msgraph` listed, io-pim-discovery under `caldav`).

Left for the-shared-kit: the shared first-run welcome replacing the missing-configuration error, `-c` taking one path per flag (`CALENDULA_CONFIG` and the `:` delimiter going with it), typed account resolution through pimalaya-config 0.4's `take_account`, and the plain text output.
