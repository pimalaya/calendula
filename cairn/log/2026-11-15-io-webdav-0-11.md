# io-webdav 0.11

calendula moves to io-webdav 0.11.0, and the two CalDAV requests it pumped by hand over the client's stream, `caldav report raw`'s REPORT and `account check`'s PROPFIND on a pinned `caldav.home`, go through `WebdavClientStd::run`: a server that closed the connection before answering gets them again on a fresh one, as every other CalDAV request, and a refused raw REPORT carries its code. The new `href` fields need nothing, calendula keying nothing on DAV ids. calendula's part of lines K27 and W10 of the CLI alignment round. Capability **backends** moved.

- **src/caldav/report/raw.rs**: the REPORT through `client.run`; `run_report` goes.
- **src/account/check.rs**: `check_caldav`'s PROPFIND through `client.run`.
- **Evidence**: on the hand-run code over io-webdav 0.11, `a_raw_report_is_sent_again_on_a_fresh_connection` and `a_home_propfind_is_sent_again_on_a_fresh_connection` failed `HTTP/1.1 send failed: reached unexpected EOF`, and `a_refused_raw_report_is_coded` found no code on a 403.

CHANGELOG (Changed, Fixed). Spec: backends ("A CalDAV request survives a closed connection", added).
