# io-webdav 0.10

calendula moves to io-webdav 0.10.0: a calendar update goes through io-webdav's `CaldavCalendarPatch`, its own PROPPATCH gone, so a clear is sent again on a fresh connection as every request is; a CalDAV calendar or item id lists percent-decoded where it encodes back to the served segment, a calendar found by either spelling; a colour is written as Apple's `calendar-color`, which iCloud keeps. calendula's part of line W8 of the CLI alignment round (W5, W6, W7). Capability **backends** moved.

- **src/caldav/backend.rs**: `update_calendar` builds a patch for the colour, then one for the name and the description, the colour still first and alone; `patch` goes; `listed` compares the paths `rfc4918::collection_path` builds, for the existence check and the colour read back after a create.
- **src/caldav/client.rs**: `proppatch` and `accepted` go.
- **src/caldav/proppatch.rs**: `caldav proppatch` builds the patch, setting what it is given, clearing nothing.
- **Evidence**: on io-webdav 0.9.1, `a_colour_is_written_in_apples_namespace` found the inf-it namespace, `a_clear_is_sent_again_on_a_fresh_connection` failed `connection reset`, `a_calendar_is_found_by_either_spelling` listed `My%20Cal` and `a_listed_item_id_is_decoded` `My%20Event.ics`; on 0.10 with the string comparison, `calendar update My%20Cal` failed `calendar-not-found`.
