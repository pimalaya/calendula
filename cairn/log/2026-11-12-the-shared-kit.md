# The shared kit

calendula moves onto pimalaya-cli and pimalaya-config 0.4 in one step, as Ortie and Himalaya did between 2026-11-10 and 2026-11-12 and cardamum the same day (dc2eacd). Change 4 of the-family-standards, carrying F1, F7, B3 and G2 of the abandoned cli-alignment-leftovers.

- Cargo.toml: pimalaya-cli 0.4 (`prompt`, `terminal`; `build` for the build script), patched to cli 0fbe5dd597ec48419eac87a9372c0c0d1f40f6f3 while `records::Records` waits for the family release; pimalaya-config 0.4 (`toml`, `secret`); clap without its default features (`derive`, `error-context`, `help`, `std`, `suggestions`, `usage`), so help prints without colour and unwrapped. crossterm leaves the direct dependencies, unicode-width stays for the agenda grid. The lock drops comfy-table, terminal_size, the anstream family and a second dirs.
- src/cli.rs: `CalendulaCli` and `CalendulaCommand` became `Cli` and `Command`, with pimalaya-cli's `footer!` under the help; `-c` is `ConfigFlags`, one path per flag, `CALENDULA_CONFIG` and the `:` delimiter gone; the shared commands come from their modules. `load_config` gave way to `Config::load`, and `resolve_account` takes the account through the shared `take_account`, returning its name too, which `account check`, `build`, `PimdirBackend::build` and the caldav, gcal and vdir client builders now all go through. `meet_bare_invocation` and `welcome()` mirror Himalaya's (`Welcome to Calendula, the CLI to manage calendars.`, then `event list`).
- src/main.rs: a `ConfigMissingError` a person meets (`is_wanted`) prints the welcome on stderr and exits 1; the header describes the welcome, `-c` and the plain output.
- src/config.rs: `TomlConfig` gains `sample_url` and `accounts` and loses `take_default_account`, `NO_CONFIG_HINT` going with it. `TableConfig`, `TableArrangementConfig`, the four `*ListTableConfig`, the three `AccountListing*Config`, `CalendarListConfig` and the crossterm colours are gone, with src/shared/table.rs and the getters and merges of src/account/context.rs. The top-level and account blocks keep denying no unknown key, Himalaya's shape and the one a build without a backend needs, its block being compiled out: a leftover `table` (top level or account) and top-level `account` table are refused by name (`TableRemovedConfig`, `AccountRemovedConfig`), as `todo` and `journal` are, while a colour key under `event.list.table` or `item.list.table` fails as an unknown field of its leaf block (the field `table`, where `page-size` was expected, with its line). `caldav.alpn` joins `gcal.alpn` and `msgraph.alpn`, the client no longer pinning `http/1.1` itself.
- Plain text: `account list` (NAME, BACKENDS, DEFAULT), `vdir list` (ID, PATH, NAME), `gcal acl list` (ID, SCOPE, ROLE, VALUE), `gcal colors` and the two lists of `pimdir status` print as `Columns`; `calendar list`, `caldav list` (gaining its ctag and sync token in text), `gcal calendars`, `gcal free-busy` and `pimdir search` as `Records`; `account check`, `caldav discover`, `gcal settings` and the head of `pimdir status` as `Fields`. `event list` and `event find` print as Himalaya's `envelope list` (src/shared/listing.rs: `Account: <name> (<backend>)`, `Calendar:`, `UID:` for find; headerless id, start, end, summary rows; `Page:` and `Next page:`), and `item list` (entity tag, size, id last) and `gcal instances` (id, status, start, end, summary; `Event:` in the header) take the same frame. Every server or user string goes through `sanitize::text`, the write sentences' ids included; ariadne draws without colour; the agenda grid lost the reverse-video and blue escapes it wrote even into a pipe, and its labels are defused. `-w/--max-width` left `calendar list`, `event list`, `event find`, `item list` and `pimdir search`. `table_times` became `row_times`.
- Paging, on the coordinator's pointer to cardamum: `CalendarItemQuery` carries a `skip` and `take` window in place of `page` and `page_size`; `CalendarClient::list_items` takes the page and asks for one item past it, popping it into `CalendarItemPage { items, more }`, so `, the last` and `Next page:` are exact on every backend. `paginate` became a plain `window` cut; the pimdir `Window` takes the window; gcal stops fetching once the resources its events fold into (`item_count`, sharing `masters` and `folds` with `resources`) cover the window, where it counted events. `-s 0` lists every item where it listed none. The JSON of `event list`, `event find` and `item list` gains `nextPage`, the page number following or `null`.
- G2: `CalendarClient` keeps one `SecretResolver` and passes it to every open, `CaldavBackend::new` taking it as the gcal and msgraph backends do, so a backend reopened after a composer runs no credential command twice. The protocol clients' `account` fields that only carried the table style (`CaldavClient`, `VdirClient`) are gone; `GcalClient` gains the account name for the instances header.

Tests, each seen failing against the old code in a scratch copy (adapted to its signatures where the API moved): `a_delimited_config_value_stays_one_path` (the old `-c` split it into three), `a_max_width_is_refused`, `an_unknown_account_lists_the_held_ones`, `several_default_accounts_are_refused_naming_them`, `a_colour_key_is_refused`, `a_leftover_table_or_account_table_is_refused`, `a_caldav_alpn_is_read_and_defaults_to_http_1_1`, `a_reopened_backend_runs_its_secret_command_once` (the old client ran the command twice), and tests/event_list.rs, byte-exact over a vdir account (`Page: 1, events 1 to 2` with `Next page: --page 2`, then `Page: 2, event 3, the last`), which read the old bordered table. `a_missing_configuration_is_typed_for_the_welcome` has no 0.3 type to fail on; the old binary under `script` printed the bare error where the new one prints the welcome. tests/first_run.rs follows Himalaya's: help over an existing and over a broken configuration, the missing path and no welcome with stderr piped (failing on the old bare invocation, which printed the help), the failure object under `--json`. Also new: byte-exact `event list`, `item list`, `account list`, `calendar list` and `pimdir search` outputs, the client's paging over a vdir calendar, and gcal's fold count. 259 unit tests and 7 integration tests pass.

Verified: `cargo fmt`; `cargo clippy --all-targets -D warnings` clean with the default features, `--all-features` and `--no-default-features --features rustls-ring` with each of vdir, caldav, gcal, msgraph and pimdir (`rustls-ring` alone still fails, on the no-backend errors every-feature-set-builds-clean owns, none new); `cargo test --all-features`. `json-schema -d` writes the same 48 files: `calendula-event-list`, `calendula-event-find` and `calendula-item-list` gain `nextPage`, and ten others differ in descriptions only (no "rendered", "row"). Under `script` with an empty home, bare `calendula` and `-c <missing> event list` print the welcome with the `curl` command and exit 1, `--json` prints the failure object; a scratch vdir account lists, reads and checks in the new shapes, and a colour key, a `table` table and `-w` are refused.
