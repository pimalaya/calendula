# The shared REPL and MCP server

Change 10 of the-family-standards. calendula gains `repl` and `mcp` on pimalaya-cli's shared core (the 0fbe5dd git pin, its `repl` and `mcp` features now on), as Himalaya, Ortie, cardamum and comodoro run them.

- src/session.rs: every command runs over a `Session` keeping the unified `CalendarClient`, built on first use through `CalendarClient::resolve` and dropped when a command fails; `Command::execute(printer, session)` dispatches, the sixteen unified commands take `&mut CalendarClient` (they took it by value), `event` and `item` run over `session.run_unified` but for `build`, the protocol commands build their own client as before. src/main.rs builds a fresh session per run.
- src/repl.rs: pimalaya-cli's `Repl` over the full `Command` tree, `-b` and `--backend` fixed; `repl` and `mcp` refused (`Cannot start a session inside a session`), the composer refused by name on `event build|create|update` and `item build|create|update` (`Cannot run the composer (-i) inside a session; ...`). `read_source` calls `pimalaya_cli::session::check_stdin(ErrorCode::StdinTaken)` on `-`, the new code `stdin-taken` in src/error.rs.
- src/mcp.rs, copied from himalaya/src/mcp.rs and cardamum/src/mcp.rs: sixteen classified leaves, `account_capability`, `calendar_list`, `event_list`, `event_read`, `event_find`, `item_list`, `item_read` reading, the calendar writes and the six event and item writes (kind `Schedule`) under `--allow-write`; `event agenda`, `event build` and `item build` excluded, no protocol tool. `capability::serves` (as cardamum's) hides a tool whose verb the backend declares `none`. `Grammar` drops `interactive` and `composer` always, and `attendee`, `add-attendee`, `remove-attendee`, `organizer` and `send-updates` without `--allow-send`, which requires `--allow-write` (clap `requires`). `readOnlyHint` on reads, `destructiveHint` on updates and deletes, `openWorldHint` on the six item writes, and only under `--allow-send`. `INSTRUCTIONS` names the tools, the gates and the ATTENDEE rule. The server hands the client it built to resolve the backend to the session, so the first call opens no second one. src/cli.rs runs `mcp` under `exit_on_failure`, keeping the welcome for a person missing a configuration.
- The sending guard: `PATHS_CLOSED` and `SENDING_CLOSED` statics in src/mcp.rs, read by `read_source` (a path is no way in) and by `CalendarClient::refuse_invitations`, called first in `create_item`, `update_item` and `delete_item`: inside a server without `--allow-send`, the contents written are checked with `ical::invites` (any component naming `ATTENDEE`, a VALARM's included, bytes that do not parse counting as naming one), then, on an update or a delete, the stored copy, read once; a hit fails ``Cannot <verb> an item naming an attendee (ATTENDEE) without --allow-send: the server or a sync may notify them``. It holds on every backend, vdir and pimdir included, a sync pushing their writes to a server that schedules.
- Cargo.toml: serde_json moves from the dev-dependencies to the dependencies (`std`), src/mcp.rs building tool definitions. src/json_schema.rs `SILENT` gains `calendula-repl` and `calendula-mcp`.
- README (a feature bullet, REPL and MCP subsections), CHANGELOG (`repl`, `mcp`, `stdin-taken`), the src/main.rs header (meta commands, a Sessions section, stderr carrying the REPL's JSON-session help and the server's failures), the `--backend` help.

Tests, each seen failing first: tests/repl.rs (6) and tests/mcp.rs (11) failed against the old binary, which has neither command; on the scaffold, before the guards, `what_cannot_run_in_a_session_is_refused_and_the_session_goes_on` and `an_ical_source_is_taken_as_text_never_as_a_local_path` hung (the command blocked on the stdin the session holds) and `a_write_naming_attendees_needs_allow_send` failed (the invitation was written); the path half of the second failed with `paths_closed` removed (the file was read and stored), and the composer half of the first with the composer refusal removed. tests/first_run.rs `an_mcp_server_missing_its_configuration_leaves_stdout_empty` failed against the old binary. Unit: `ical::tests::an_item_invites_whoever_it_names_as_an_attendee` failed against a stub; `mcp::tests::the_instructions_name_existing_tools` and `every_unified_leaf_is_classified` added.

Verified: `cargo fmt`; clippy `--all-targets -D warnings` and the tests clean over the eleven sets of the `features` job; `cargo test --all-features` (268 unit tests and every integration suite). `json-schema -d` before and after: 49 schemas both, `calendula-error` and `calendula-account-check` gaining `stdin-taken` in the code enum and its description, nothing else. An MCP session over stdio on a scratch vdir account: `initialize` names `calendula` 0.2.0 and 2025-06-18; `tools/list` lists the seven reads without flags, sixteen tools under `--allow-write` (no scheduling property, every `openWorldHint` false) and under `--allow-write --allow-send` (the five scheduling properties, `openWorldHint` true on the six item writes); `--allow-send` alone exits 2 naming `--allow-write`; `calendar_list` and `event_list` return `structuredContent` valid against their `outputSchema` (Python jsonschema, Draft 2020-12), every input and output schema a valid object schema; stderr empty; `event_delete` of an event inviting a guest refused under `--allow-write`, the file kept.

Spec: repl (new), mcp (new), commands (A JSON error carries a stable code gains `stdin-taken`; Nested execute and Output goes to stdout modified).

Left: an argument the backend does not serve (`if-match` on vdir, `online-meeting` off pimdir, `send-updates` off gcal) stays a property and answers `capability-missing`; the four create and update tools carry no `outputSchema` (their schema is `anyOf` the write and the abandoned composer edit, which no tool reaches).
