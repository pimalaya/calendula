# The wizard picks, and asks once

The wizard follows the Pimalaya Android app's onboarding, transposed to the CLIs with the owner's approval on 2026-11-08, on the shared steps of pimalaya-cli (patched to the local checkout, 6d8daa7 then f976e40, which names an API token as such in the "goes to" line; to become a git rev at push).

- Discovery moved to io-pim-discovery 0.11 (without `rfc9728`, whose resource lookups ignore the discovery deadline) and asks for CalDAV, `Gcal` and `MsgraphCalendar`. No breaking change of 0.10 or 0.11 touched calendula's code: it never matched `DiscoveryConfigSource` nor built a config, and a resolver that does not answer now fails the lookup through the existing `?`.
- src/wizard/search.rs turns the configs into routes (protocol, server, sign-in): every OAuth grant and issuer of a server folds into one OAuth route, a route reading as one listed is dropped, a server advertising nothing gets a password route, and a service this build has no backend for is skipped. The ranking puts a provider API before CalDAV, keeps servers in discovery order, and orders the sign-ins of one server by whether `ortie` is on the `PATH`.
- src/wizard/plan.rs holds the review row, the change list (Auto, the routes, `Custom server URL`, the host or the URL added only where two labels collide) and the server URL parser. src/wizard/sign_in.rs holds the sign-in: `prompt_password`, the test (`check_account`), `prompt_store` at `calendula-<account>-<backend>`, `ortie::sign_in` with `calendula-<account>` or, Ortie missing, one line then `prompt_token`, and the refusal menu. src/wizard/caldav.rs is gone; secret.rs keeps the converters and the broker list.
- The account name is now derived and suffixed inside `discover::run`, which takes the taken names, since the Ortie account and the keyring entry are named after it: suffixing after the sign-in would have stored the new account's password over an existing account's keyring entry.
- `msgraph.user-id` is no longer rendered at its `me` default (`skip_serializing_if`), so a generated msgraph block is the token alone, as config.sample.toml documents it; the test writing that block failed with `msgraph.user-id = "me"` before the attribute.

Decided differently from the brief: a typed server URL is encrypted only at both prompts (`http://` refused naming it, `caldav://` read as `https`), following the flow and the Android requirement "Setup accepts encrypted servers only", one parser serving both prompts; the network wizard stays gated on the caldav feature (a typed server is a CalDAV one), so the wizard gates are unchanged and gcal and msgraph are offered when compiled with caldav; discovery is not run secure-only, a discovered `http://` root still being offered.

Verified: 288 tests pass with all features (21 new in the wizard: dedupe, grant folding, the password fallback, skipped services, ranking with and without Ortie, discovery order, API before CalDAV, Graph routing, the review sentences, the change labels, the server URL parser and its refusals, the login rule, the keyring entry, and the CalDAV, gcal and msgraph blocks as rendered). clippy is clean with all features, the default set, each backend alone with rustls-ring, and the wizard with each; `--no-default-features` builds with the warnings it had before. A pseudo-terminal run (`script`) of `calendula -c <scratch> configure` refused `http://localhost:1/`, then took `caldav://localhost:1/dav/` through `Sign in with: Password`, the review row `Calendar  CalDAV at localhost:1, with your password`, `Login:`, `Your password goes to https://localhost:1/dav/`, the refused test (`caldav: connect localhost:1: Connection refused`), the refusal menu, `Back to the review`, `Change calendar`, `Custom server URL` refusing `http://x.example.org/` and an empty answer keeping the pick; a folder input appended `cals-2` to a scratch configuration holding `cals`. Discovery and Ortie were not run: no network, no real accounts, and Ortie's `configure [INPUT] --service --name` is built in parallel.

Spec: wizard (ADDED The Auto plan and the review, The user sees where a password goes, A password is typed once and stored, The refusal menu, OAuth hands off to Ortie, Nothing discovered asks for a server URL; MODIFIED Input orients the flow, A typed server URL is configured as given, Connection tested before printing, The wizard covers the discoverable backends only; REMOVED One entry per service, then auth, OAuth folds into the API token, Stop when nothing is discovered).
