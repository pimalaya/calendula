# io-pimdir 0.19

Calendula moves to io-pimdir 0.19.0 (pimdir storage-draft-15) and ical-rs 0.7.3, vcard-rs 0.6.1 and mime-rs 0.2.1 coming with it. Capability **backends** moved.

- **Store**: a store or sync state of draft-14 is refused (`store-version`), never migrated; the test standing for a newer engine's store now stamps `storage-draft-16`.
- **Created id**: `create_item` states the `UID`-derived key on its `add` and no `hash:` key, and reports `PimdirEnqueued::link_id`, the key io-pimdir derives from the body it holds, a foreign body's `X-PIMDIR-` properties taken out. Before, a foreign event with no `UID` was keyed by the `hash:` of the bytes before that stripping, a key naming no body the store holds, which io-pimdir 0.19.0 refuses with `hash-key-mismatch`. A `UID` key stays stated so a second create of a queued `UID` is still refused `item-duplicate` at enqueue: io-pimdir's duplicate check reads only the keys pending rows state.
- **Evidence**: `a_uidless_foreign_event_is_keyed_by_its_stripped_body` (fails against the former key with `hash-key-mismatch`).
