# The releases of 2026-11-21

Calendula moves to io-http 0.9.0, io-oauth 0.8.0 (dev), io-gcal 0.6.0, io-jmap 0.11.0, io-msgraph 0.10.0, io-webdav 0.13.0, io-pimdir 0.19.1 and pimalaya-stream 0.4.1, io-proxy 0.3.0 following through the lock. A dependency move, no proposal, no behaviour change.

- **Features**: the io-* `client` feature, which named the blocking client, is now `std` (family rule cargo-006), `client` gating the coroutines. io-gcal, io-jmap and the dev-dependency io-oauth name `std` in place of `client`, and the `jmap` and `msgraph` features enable `io-jmap/std` and `io-msgraph/std`; io-webdav already named `std`.
- **Lock**: `cargo update -p` on those crates moved them alone in Cargo.lock.
- **Code**: no source change.
- **Evidence**: `cargo clippy --locked --all-targets -- -D warnings` and `cargo test --locked` over the CI feature sets of .github/workflows/tests.yml: clippy clean on every set; tests green on every set (561 passed, 20 ignored on the default and `--all-features` sets) but `--no-default-features --features rustls-ring,vdir`, where `a_uid_is_read_by_event_read_and_a_search_takes_a_query` (tests/event_list.rs:171) expects `event search` refused `capability-missing` while that build compiles no `search` subcommand (`#[cfg(feature = "pimdir")]` in src/shared/event/cli.rs), clap exiting 2 with `usage-invalid`: a test gap of the tree, independent of this move, left open. `cargo fmt --check` clean.

io-pimdir 0.19.1 fixes the sync engine, which calendula does not run: no CHANGELOG line. Capabilities moved: none.
