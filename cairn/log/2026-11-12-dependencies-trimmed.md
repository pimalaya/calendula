# Dependencies trimmed

calendula's dependencies take Ortie's and Himalaya's shape (ortie 2026-11-09-dependencies-trimmed and 2026-11-09-deny-warnings-cleared, himalaya 2026-11-11-dependencies-trimmed), change 6 of the-family-standards.

- Cargo.toml: every dependency, build and dev ones included, takes `default-features = false` and names its features, each checked against the item it gates rather than by compiling alone, feature unification hiding a missing one: chrono `clock`, `serde` (the agenda's JSON keys are `NaiveDateTime`s) and `unstable-locales`, ical-rs `parser` and `tzdb` (`tzdb::vtimezone`), jiff `std`, `tz-system` and `tzdb-bundle-always`, schemars `derive`, serde `derive` and `std` (the accounts `HashMap`), simd-cpu `std`, the io-* crates and the pimalaya kit as before. schemars loses `std`: no calendula schema type holds a type it gates, which a check against a pimalaya-cli copy leaving it off confirmed, pimalaya-cli turning it on for its own `PathBuf` fields. anyhow loses `std`, every item calendula uses (`Context`, `downcast_ref`, the `?` conversion) going through `core::error::Error` on its 1.89 MSRV, where Himalaya, Ortie and Cardamum name it. ariadne, getrandom, humansize, log, secrecy and unicode-width (`width` only, not `width_cjk`) take none; getrandom (the `UID` calendula mints) and humansize (the `item list` size column) are used and stay. url takes neither `std` (`ParseError` is a `core::error::Error`) nor, outside `caldav`, `serde`: `caldav.home` is the only `Url` deserialized, so the `caldav` feature turns it on. io-vdir loses `serde`, calendula mapping its types to rows of its own. serde_json moves to the dev-dependencies with `alloc`, the tests being its only user (`from_slice`, `from_str`, `json!`, `to_string`, `to_value`, `Value`); it stays in the tree under schemars and pimalaya-cli. tempfile loses `getrandom`; toml takes `parse` and `serde`. clap, already trimmed, and pimalaya-cli's `prompt`, which the composer's re-edit question asks through in every build, are unchanged.
- `idna_adapter = "=1.0.0"` drops the 21 ICU4X crates (displaydoc, icu_collections, icu_locale_core, icu_normalizer, icu_normalizer_data, icu_properties, icu_properties_data, icu_provider, litemap, potential_utf, stable_deref_trait, synstructure, tinystr, writeable, yoke, yoke-derive, zerofrom, zerofrom-derive, zerotrie, zerovec, zerovec-derive): a CalDAV `home` with a non-ASCII host is refused when the configuration loads (`invalid international domain name`, pointing at the line), a `server` when the account connects, their Punycode form working. `a_non_ascii_host_is_refused` (src/caldav/client.rs) was seen failing on the ICU4X back end, which accepted `https://bücher.example/dav/`; the 0.2.0 binary loaded the same `home` the new one refuses.
- `parse_server` prefixed `https://` to any `server` that failed to parse, not only to a bare authority, so with the ICU4X back end gone `https://bücher.example/dav/` still parsed, as host `https` with path `//b%C3%BCcher.example/dav/`, and `https://dav.example.org:99999/` the same way, its out-of-range port failing whatever the IDNA back end. It now prefixes only a string without a scheme (`RelativeUrlWithoutBase`) or one whose first label url read as a scheme (`dav.example.org:8443`), refusing every other parse error. `a_non_ascii_host_is_refused` failed on that fallback after the switch, and `a_malformed_url_is_refused_rather_than_prefixed` on the old `parse_server`. The Google Calendar and Graph hosts are fixed ASCII names; `caldav.discover` was not checked, its domain going to DNS first.
- src/main.rs: `main` calls `SimdCpu::install_detected()` first (simd-cpu 0.1, `std`), so the base64 and quoted-printable codecs io-http (the CalDAV `Basic` header), io-msgraph, io-proxy, mime-rs (under io-pimdir's `search`) and pimalaya-cli call run the detected backend instead of the portable one. simd-cpu 0.1.0 was already in the lock under base64-codec, one token for all of them. ical-rs runs neither codec here, its `base64` and `quoted-printable` features being off.
- deny.toml lists Ortie's and Himalaya's targets under `[graph] targets`, which clears the windows-sys duplicate; the allowed licences are the ones the tree carries: Apache-2.0, BSD-3-Clause (domain, octseq, subtle, encoding_rs), ISC (ring, untrusted), MIT, MPL-2.0 (option-ext), Unicode-3.0 (unicode-ident) and Zlib (foldhash 0.2, under rusqlite's hashlink). 0BSD, `Apache-2.0 WITH LLVM-exception` (blake3, rustix and linux-raw-sys each offer Apache-2.0 beside it) and CDLA-Permissive-2.0 leave. `allow-org.github = ["pimalaya"]` stays while the pimalaya-cli git pin lives.
- `CaldavConfig::server` and `home` document the ASCII host.
- The `[patch.crates-io]` pimalaya-cli pin is unchanged.

Capabilities moved: packaging (cairn/spec/packaging.md: "Dependencies name their features", "Hosts are ASCII" and "Dependency checks pass clean" added), config (cairn/spec/config.md: "CalDAV locates its home-set three ways" modified, a `server` failing to parse refused).

Verified: `cargo fmt`; `cargo clippy --all-targets -D warnings` with the default features, `--all-features`, and `--no-default-features` with `rustls-ring` plus each of vdir, caldav, gcal, msgraph and pimdir, and with `native-tls,caldav` (the devshell carrying no OpenSSL, which Himalaya's shell.nix has, it ran with `PKG_CONFIG_PATH` on nixpkgs' openssl.dev; `--all-features` builds it through `vendored`). `--no-default-features --features rustls-ring`, a build with no backend, fails on dead code and unused variables (27 errors in the binary, 29 with its tests), the same diagnostics as on b6875e0. `cargo test --all-features` (269 tests: 262 unit, 2 event_list, 5 first_run). `cargo deny check` (advisories, bans, licences and sources ok). `json-schema -d` writing the same 48 schemas from the default release build before and after. Release binary (default features, `cargo build --release --locked`, one build each, from the repository's target directory): 12,182,352 bytes before, 12,049,872 after (-132,480, -1.1%). Normal tree (`cargo tree -e normal --prefix none`, unique crates, calendula included): 163 before, 142 after with the default features; 171 before, 150 after with every feature. Cargo.lock: 263 packages before, 242 after.
